# Validation

## Verify the text

Check correctness, completeness, consistency, clarity, feasibility, and
testability.

## Validate the need

Check that the requirement solves the stated problem and supports the desired
outcome. A technically clear requirement can still solve the wrong problem.

## Stress-test

Use:

- normal scenarios;
- negative scenarios;
- boundary values;
- permissions;
- failure and recovery;
- data quality;
- timing and concurrency;
- compliance and audit needs.

## Agent use

Ask the agent to produce counterexamples and missing cases.
Do not treat generated cases as stakeholder approval.

## Gate G3

Pass when gaps, conflicts, edge cases, and acceptance evidence are reviewed.
